KEEPING v3 에서 쓰던 방식을 표준화한 것입니다. 사람이 자는 동안 돌릴 **정적 세트**와, 사람이 옆에 있을 때 돌릴 **실행 검증 세트**를 나눠 만듭니다.

`docs/prompts/` 아래에 번호를 이어서 파일을 만듭니다 (기존 최대 번호 + 1). 각 파일은 새 대화창에 그대로 붙여넣어 쓰는 자기완결 문서입니다.

**세트 A — 정적 작업 (night 모드에서 실행)**
```markdown
# 세트 #NN — <목표> (정적, 읽기/쓰기만)
> 새 대화창에 붙여넣기. 시작 전 사용자가 `/core:mode night` 로 전환.
> 선행: <앞 세트 번호>

## 0. 절대 제약 (다른 모든 지시보다 우선)
| 금지 | 이유 |
| 빌드·테스트 실행 | 권한 승인할 사람이 없음 (하네스 night 모드가 차단) |
| 서버·DB·k6 접근 | 인프라 담당 영역 |
| git 쓰기 | 사람이 검토 후 커밋 |
허용: 파일 읽기/쓰기, grep/find/cat, git log/diff/blame (읽기)
멈추지 마라. 판단이 갈리면 가장 안전한 쪽으로 쓰고 가정을 워크로그에 남겨라.
컴파일을 못 돌리므로: 참조 클래스·메서드는 실제 파일을 열어 시그니처 확인, import 경로 정확히.

## 1. 목표와 완료 조건
## 2. 작업 단계 (파일 단위)
## 3. 워크로그 — `.harness/worklog/NN.md` 에: 바꾼 파일, 가정, "사람이 실행할 명령" 목록
```

**세트 B — 실행 검증 (사람 동석, standard 모드)**
- 세트 A 워크로그의 "사람이 실행할 명령"을 한 번에 묶어 먼저 실행 (승인 요청을 몰아서)
- 실패 시 수정 범위는 "돌아가게 만들기"만. 새 기능 금지. push 는 사람이.

작성 후 두 파일 경로와 실행 순서를 알려주세요.
