# 막히면 미뤄두고 계속하기

사용자는 자리를 비울 수 있어요. 중간에 질문하면 그동안 아무 일도 진행되지 않아요.
그래서 **결정이 필요한 부분만 빼두고 나머지를 끝까지** 해요.

## 언제 미루나
- 요구사항이 두 가지로 해석되고, 잘못 고르면 되돌리기 번거로울 때
- 화면에 보이는 값·정책·데이터 삭제처럼 사람이 정해야 하는 것
- 외부 정보(키, 계정, 서버 주소)가 필요할 때

## 언제 미루지 않나
- 작업 시작 전 계획 단계의 확인 질문 → 그때 바로 물어봐요
- 코드에서 확인하면 알 수 있는 것 → 직접 찾아요
- 되돌리기 쉬운 사소한 선택 → 합리적으로 정하고 "임시 처리"에 적어요

## 방법
1. `.harness/pending-decisions.md` 에 추가 (번호는 이어서):
   ```markdown
   - [ ] D3: 탈퇴한 사용자의 게시글을 목록에서 숨길까요, "탈퇴한 사용자"로 표시할까요?
     - 막힌 이유: PostResponse.author 가 null 이 될 수 있어 화면 처리 방식이 갈림
     - 선택지: A) "탈퇴한 사용자" 표시 (추천 — 글 맥락 유지) / B) 목록에서 제외
     - 같이 보류한 작업: PostList.tsx 작성자 영역, PostQueryRepository 필터
     - 임시 처리: 백엔드는 author=null 그대로 반환, 화면은 손대지 않음
   ```
2. **겹치는 작업만** 보류: 그 결정에 따라 코드가 달라지는 파일·기능만 건너뛰어요.
3. 나머지 작업은 끝까지 진행해요.
4. 다 끝나면 하네스 Stop 훅이 질문할 차례를 알려줘요 → 한 번에 질문.
5. 답을 받으면 `[x]` 로 바꾸고 보류한 작업을 이어가요.
