# 기록 규칙

| 상황 | 어디에 | 형식 |
|---|---|---|
| 기술/설계 선택 | `docs/decisions.md` | `YYYY-MM-DD \| 결정 \| 이유(검토한 대안과 근거)` |
| 도메인 경계·동기/비동기·저장소 같은 큰 결정 | `docs/adr/NNN-slug.md` | 맥락 / 결정 / 대안 / 결과(트레이드오프) |
| 같은 실수 2회 | `docs/failures.md` | `날짜 \| 무엇이 \| 원인 \| 재발 방지(훅/테스트/규칙)` → hook-promotion 스킬 |
| 성능 측정 | `docs/perf/` 또는 ADR | 변인 하나 / 반복 측정 횟수 / CV / 전후 수치 / 결론 |

원칙
- **실제로 검토한 대안과 실제 이유만** 적는다. 그럴듯한 근거를 지어내지 않는다. (면접·자소서에서 그대로 설명할 수 있어야 함)
- 수치는 측정한 조건(하드웨어, 부하 모델, 반복 횟수)과 함께 적는다. 조건 없는 수치는 쓰지 않는다.
- 부하 테스트에서 찾은 병목은 "부하 테스트에서 재현·해결"로 적고, 운영 장애처럼 쓰지 않는다.
